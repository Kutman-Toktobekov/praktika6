# Практическая работа № 6
## Синхронизация потоков в Python

### Цель работы
Изучить синхронизацию потоков с помощью семафоров, мьютексов, условных переменных и барьеров. Проверить корректность работы многопоточных программ.

### Структура проекта

- `producer_consumer.py` — задача производителя и потребителя в двух вариантах.
- `barrier_demo.py` — барьер для четырёх потоков и трёх фаз.
- `lost_wakeup_demo.py` — демонстрация ошибки при неправильном ожидании условия.
- `violations.log` — журнал нарушений.

### Задание 1. Производитель и потребитель

Реализован кольцевой буфер вместимостью 5 элементов без использования `queue.Queue`.

**Вариант A: семафоры и мьютекс**
- Семафор `empty` отслеживает свободные места.
- Семафор `full` отслеживает заполненные места.
- Мьютекс защищает доступ к буферу.

**Вариант B: мьютекс и условная переменная**
- Используется `threading.Condition`.
- Производители и потребители ожидают изменения состояния буфера.
- Для проверки условий ожидания используются циклы `while`.

Параметры:
- 3 производителя;
- 2 потребителя;
- 1000 элементов;
- размер буфера — 5.

### Задание 2. Проверка корректности

- Пропущено элементов: 0.

- Ошибки: отсутствуют.

Результат проверки: **УСПЕХ**.

### Задание 3. Барьер для потоков

В файле `barrier_demo.py` реализован барьер на основе `threading.Condition`.

Четыре потока выполняют три фазы работы. Каждый поток ждёт, пока остальные потоки завершат текущую фазу, и только после этого переходит к следующей.

Результат: все четыре потока завершили три фазы.

### Задание 4. Демонстрация ошибки ожидания

В файле `lost_wakeup_demo.py` используется `if` вместо цикла `while` при ожидании условия.

Другой поток отправляет уведомление, не добавляя элемент в буфер. Ожидающий поток просыпается и обнаруживает, что буфер всё ещё пуст.

Это демонстрирует, почему после пробуждения необходимо повторно проверять условие.

**Правильный подход:**
```python
with condition:
    while items == 0:
        condition.wait()
```

Классическое потерянное пробуждение также может возникнуть, если проверка условия и начало ожидания неправильно синхронизированы.
